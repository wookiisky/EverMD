# 性能验证

性能改动以相同文档、相同动作的前后测量为依据。毫秒数用于观察趋势，正确性由正文、选区、目录结果和真实 DOM 的断言证明，不把某台机器的耗时阈值当成跨平台通行标准。

## 测量边界

| 入口 | 测量内容 | 不代表什么 |
| --- | --- | --- |
| `verify:editor-performance` | 真实 CodeMirror `EditorState` 的输入及选区事务，隐藏空行分别开启和关闭 | 不包含 DOM、绘制；显示语法树从默认惰性解析范围开始 |
| `verify:performance-ui` | 离屏 Electron 的实际输入处理、一个事件循环后的强制同步布局，启动和打开文件的外部观察耗时 | 不代表输入到显示器呈现的延迟；不把赋值滚动位置的耗时当作完成滚动渲染 |
| `verify:document-statistics` | 原统计函数与新扫描函数的差分和交替微基准 | 不包含外壳更新和帧调度 |
| `verify:scroll-render` | 滚入未解析区域后，视口内容最终正确渲染 | 不作为稳定的帧率基准 |

macOS 的完全隐藏窗口在关闭后台节流后，动画帧仍可能约一秒一次。因此 UI 性能脚本不以这段等待估算用户端延迟；大纲测量单独等待后续帧收齐按钮变化。脚本不能提供的首帧呈现数据记录为 `null`。

统计和大纲的展示可以在下一动画帧更新，UI 同步计算指标不包括尚未执行的帧回调。保存、未保存状态和外部冲突判断不跟随展示延后。

## 运行与比较

```sh
npm run verify:editor-performance -- --output /tmp/editor-before.json
npm run verify:document-statistics
npm run build
npm run verify:performance-ui -- --output /tmp/ui-before.json
```

改动后使用相同命令输出到 `editor-after.json` 和 `ui-after.json`。状态基准预热 5 次、采样 30 次；窗口基准预热 3 次、采样 12 次。报告保留原始样本、中位数及 P95；启动和每次打开的观察值为单次样本，不据此宣称稳定的启动提速比例。

真实窗口一律通过 `scripts/offscreen-window.cjs` 启动。测试使用独立临时文件和 profile，结束后清理。现有 `verifyWorkdir` 会清理其他验收进程，因此 Electron 验收必须串行运行；Node 测试可以独立运行。比较时也应避免其他重负载干扰。

堆大小是在强制 GC 后读取的进程指标。结束时还打开着测试标签，起止差值不能直接解释为泄漏；检查缓存还需结合关闭标签、撤销历史和对象引用生命周期。

## 本轮测量结果

2026-10-29，在同一台 macOS arm64 机器上，以改动前的 `be8c095` 和当前工作区作对比。Node 为 24.20.0，Electron 为 44.3.0；基准使用相同脚本与文档。以下为中位耗时，不能外推为所有文档或其他平台的固定收益。

4000 段、226889 个 UTF-16 单位的文档，编辑器状态计算结果：

| 动作 | 改动前 | 改动后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 输入，显示空行 | 6.80 ms | 1.35 ms | 80% |
| 移动选区，显示空行 | 6.90 ms | 1.13 ms | 84% |
| 输入，隐藏空行 | 28.94 ms | 6.83 ms | 76% |
| 移动选区，隐藏空行 | 7.66 ms | 1.58 ms | 79% |

统计函数对 2097152 个 UTF-16 单位的中英混合文本，从 19.45 ms 降到 9.15 ms；同规模英文文本从 14.64 ms 降到 9.01 ms，空白密集文本从 23.75 ms 降到 11.27 ms。短英文文本的差距较小。20 个固定用例和 3000 个随机用例与原函数逐项比较，字符、词和段落计数保持一致。

相同 4000 段文档的真实 Electron 输入处理与同步布局结果：

| 动作 | 改动前中位数 / P95 | 改动后中位数 / P95 |
| --- | ---: | ---: |
| 输入，显示空行 | 12.60 / 42.20 ms | 2.50 / 2.70 ms |
| 输入，隐藏空行 | 30.90 / 60.90 ms | 7.00 / 7.30 ms |

两侧各 200 个标题的大纲，在正文输入后的刷新中，原先删除 400 个按钮再新建 400 个；现在新增和删除均为 0，仍更新标题的位置。这个结果只适用于标题文字和级别未变化的场景。单次启动观察值为 324 ms → 353 ms，普通大文档打开为 76 ms → 74 ms；样本不足，不据此宣称启动或打开速度得到稳定提升。

## 回归边界

- `verify:preview-analysis`、`verify:blank-lines`：文本和语法树分别失效、完整解析对照、多个变更范围、保护区开闭、暂停后恢复、撤销重做、解析刷新合并。
- `verify:document-install`：新文档一次安装配置，标签恢复保留自己的撤销、选区及搜索，任务标记范围随树推进更新。
- `verify:editor-navigation`：源码结构复用、批量替换、旧查找位置失效和局部格式修改。
- `verify:document-outline`、`verify:file-panel-model`：标题显示与位置分离，目录乱序响应、失败和展开状态。
- `verify:startup`：主动阻塞目录读取，验证多个启动文档仍能按顺序就绪，目录释放后不重复交付或覆盖正文。预载层原本就缓存 `file-opened`，该测试证明解除目录阻塞，不把旧行为描述成事件丢失。
- `verify:sidebars`：真实双侧面板、节点复用、正文换行后的大纲跳转、根列表相同时的子目录更新。
- `verify:image-export`：打印准备返回时检查全文 HTML 块与占位，再核对实际 PNG 的全部彩色行。原版也能复现“可见范围覆盖全文，但语法装饰只到第 46 块”的竞态；导出现在显式推进全文解析并刷新装饰，保留原有 5 秒准备时限，不承诺任意大小文档都能在时限内完成。
- 字节保真、文件监听、文档生命周期、模式切换、滚动渲染和导出继续使用现有对应 `verify:*` 验收。

本机隐藏窗口的 `Page.captureScreenshot` 会超时。侧栏的可选截图使用 `verify:sidebars -- --screenshots`；默认功能检查保留真实几何、主题样式和焦点断言。完整功能脚本可显式传 `--skip-selection-screenshots` 继续其他检查，并打印跳过说明；这不算通过逐主题选区像素验收。图片导出的 PNG 像素验收使用实际导出文件，已单独验证。

本轮 macOS 本地验收已通过：

- main、preload、renderer、web 四套 TypeScript 检查，桌面与 Web 构建。
- Markdown 100 个样本字节对照，文档安装与生命周期、文件监听、导航历史、空行完整解析对照、语法缓存失效、统计差分和目录模型测试。
- 真实窗口启动阻塞测试、链接导航 106 项、侧栏 51 项、源码模式切换 198 项、隐藏空行与滚动渲染、主题及段落间距。
- `verify:features -- --skip-selection-screenshots` 的 349 项功能检查；包含实际选区建立、绘制后的深色选区对比度及布局完成后的焦点恢复，不包含上文列出的逐主题像素截图。
- 桌面及移动尺寸四组 PNG 导出逐行像素检查，300 行 PDF 导出，以及列表、表格和强调导出检查。

源码模式验收包含接近阈值的约 51 万字符文档。文末切入源码与切回渲染的三次中位耗时分别为 175 ms、89 ms，通过原有性能检查；没有对照数据，不将这组数值记作提速比例。未在本轮验证 Windows/Linux 运行时或显示器呈现延迟。

本轮保持现有大文档源码模式阈值和数据保护规则。同步偏好读写、平台菜单和导出依赖仅在有新的测量证据时继续调整。

## 大目录与大文件打开的后续优化

2026-10-29，用户确认修复慢目录刷新，并优化大目录及大文件打开。以下基线是本节实施前保留的构建产物，已经包含上面的编辑器性能改动，不再是 `be8c095`。同机 macOS arm64、Electron 44.3.0，使用 `verify:opening-performance`，每组预热一次、采样五次。

```sh
# 仅基线采集允许使用明确保留的旧 dist，运行期间不能重新构建。
npm run verify:opening-performance -- --baseline --output /tmp/evermd-opening-before.json
npm run build
npm run verify:opening-performance -- --output /tmp/evermd-opening-after.json
# 出现具体性能疑点时，另采 CPU 和布局数据；带采样的耗时不混入普通基准。
npm run verify:opening-performance -- --profile --output /tmp/evermd-opening-profile.json
```

目录测量从真实打开动作到文件面板完成一轮更新并可读取布局，包含 IPC、CDP 和帧调度。单侧及双侧均保持完整目录，没有截断文件数量。首轮结果如下（中位数 / P95，单位 ms）：

| 条目数 | 面板数 | 修改前 | 修改后 | 列表元素数，修改前 → 修改后 |
| --- | --- | ---: | ---: | ---: |
| 1,000 | 1 | 45 / 48 | 33 / 34 | 8,006 → 374 |
| 1,000 | 2 | 63 / 83 | 37 / 44 | 16,012 → 748 |
| 10,000 | 1 | 807 / 818 | 36 / 39 | 80,006 → 374 |
| 10,000 | 2 | 1,649 / 1,681 | 35 / 42 | 160,012 → 748 |

首轮后测的 10 MiB CRLF 首开出现变慢，因此在源码未变的情况下复测同一套基准。复测的一万条目单侧及双侧中位数均约 35 ms，元素数量仍为 374 / 748，大目录收益可以重复观察。文件耗时如下，每格为“首次打开 / 已打开标签切回”的中位数，单位 ms：

| 文件 | 修改前 | 首轮后测 | 复测 |
| --- | ---: | ---: | ---: |
| 1 MiB LF | 181 / 180 | 185 / 178 | 179 / 170 |
| 1 MiB CRLF | 174 / 173 | 162 / 175 | 174 / 166 |
| 10 MiB LF | 1,873 / 1,788 | 1,652 / 1,672 | 1,787 / 1,774 |
| 10 MiB CRLF | 1,755 / 1,771 | 1,961 / 1,519 | 1,770 / 1,728 |

大文件结果有明显波动，复测没有重现首轮 CRLF 首开的同等变慢，也不能据此认定有稳定的首开提速。每轮只有五个有效样本，报告中的 P95 实际为这五个值的最大值，仅用于描述该轮样本。三份原始报告分别保存为 `/tmp/evermd-opening-before.json`、`/tmp/evermd-opening-after.json`、`/tmp/evermd-opening-after-repeat.json`，保留全部样本，不只选取更快的一轮。

文件面板超过 200 行时只挂载视口附近、当前焦点及首尾键盘入口。每侧使用自己的几何索引和滚动状态；普通行、返回上级、不同缩进深度的空目录提示按真实样式测量。目录读取各自完成就发布结果，不等待其他慢目录；原有帧调度仍合并绘制。

大文档保留 `512 * 1024` 个 UTF-16 单位的自动源码阈值。统计改成每任务最多扫描 256 Ki 个 UTF-16 单位，新正文取消旧任务；同步与异步共用统计语义，完整结果才更新界面。保存副本只缓存当前正文、行尾和前置内容；保存及冲突判断仍同步取得当前版本。空行保护仍完整解析，只跳过确定不存在的公式扫描。

10 MiB 文档的 CPU 采样显示，首次打开或切回仍有约 1.0–1.2 秒用于原生 textarea 布局；离开文末光标时，定位镜像还需约 0.46–0.54 秒。这些是诊断单次值，不是性能承诺。试验过 `ratio === 0` 时跳过滚动范围读取，布局总量没有明显降低，因此没有保留该分支。分段统计减少连续主线程占用，不代表减少总扫描工作，也不能据此宣称大文件首开问题已解决。

本节新增或扩展的验证：

- `verify:file-panel-model`：快速目录完成时慢目录仍挂起，快速结果已经发布；迟到旧版本不能覆盖新结果。
- `verify:file-panel-view`：纯几何索引与真实 Electron 两侧一万条目、末尾点击和右键、Tab/Shift+Tab 跨范围及两端进出、滚动/删除/排序后的焦点、主题和尺寸变化、大目录切回小目录。
- 深层空目录提示先复现后修复：深度 10 时下一行的原生位置为 211.47 px，旧虚拟位置为 196.98 px；现在按深度测量，包含 180 px 窄侧栏英文换行对照。
- `verify:statistics-scheduler`：分块词边界、CRLF、取消及已经出队的旧回调；外壳在下一帧请求执行之前也拒绝旧正文的完成结果。
- `verify:document-file-content`：实际序列化字节、混合行尾、编辑/撤销、外部重载、标签恢复及前置内容变化。

本节实际通过四套类型检查、桌面构建、Markdown 100 个样本字节对照、统计 20 个固定及 3,000 个随机差分、空行/目录模型/几何测试，以及真实窗口侧栏 51 项、源码模式 198 项、文档生命周期 22 项和启动验收。前后打开基准还逐次核对正文长度与首尾、可编辑状态、干净状态，以及临时文件的完整字节和 mtime。未验证 Windows/Linux 运行时和显示器呈现延迟。
